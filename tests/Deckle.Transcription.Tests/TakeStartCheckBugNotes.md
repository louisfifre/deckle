# Take start check bug notes

## A warm-up that threw was never noticed until Stop, and the take recorded for minutes into nothing

- Trigger: a dictation take started while another application used about 38 GB of memory (2026-11-02). The warm-up inference, started by `BeginPrime` beside the capture, threw a native `SEHException` from the Vulkan backend.
- Observed: the recording went on for five minutes. Stop then reported `Pipeline crashed` and discarded everything. The model stayed loaded on a context that may have been corrupt.
- Cause, established from the logs and the code: the streaming consumer awaited the prime at its gate and handled only a prime that returned `false`. A throw faulted the consumer task, which nobody observed until `session.Completion` was awaited at Stop. Nothing in the engine ended a take by itself either: `_recordCts` was cancelled only by the Stop press and by Dispose. Two comments claimed the user had already been told on that path, which was false for a throw.
- Cause, inferred and not proven: that memory exhaustion made the native call throw. The log shows the throw and the memory state of the machine at that time, not the allocation that failed.
- Second cause, same incident: the prime was skipped when the backend reported its model as loaded, so a model left unusable by an earlier failure was only tested by a real utterance. `WhisperBackend.IsModelLoaded` stays true after a native throw.
- Third cause, same incident: `WhisperBackend.TranscribeSync` skipped `nativeAllocs.Free()` and left both stopwatches running when `whisper_full` threw, so a retry started from a dirty backend.
- Fourth cause, same incident: the HUD answered the finish signal of a failed take with `Hide()`, queued right after the failure message, so any message shown at that moment (this one, but also the microphone error and `Pipeline crashed`) was gone within a frame.
- Violated invariants: a failure of the inference path shows at the start of the take, not at its end; a gate never throws; a live take that cannot be transcribed does not keep recording; a warning or an error stays on screen for its own duration.
- Fix: the prime runs on every take, dictation or file batch, also on a loaded model. A throw or a native error code fails the test; the engine unloads the model through the backend, reloads it and tests again, silently. A second failure makes the gate return `false` and nothing escapes it. The streaming consumer then stops the take itself (state to Stopping, capture token cancelled, reason kept in `_selfStopReason` because a cancelled capture reads as Completed), and the pipeline ends the take with one `Engine_TranscriptionUnavailable` message and the `transcription_unavailable` reason. The monolithic pipeline ends the same way at Stop. A file batch stops after its first file instead of failing every file. `WarmupTestFailed` logs each failed test with available and total physical memory and available commit and commit limit. `HudHidePolicy` makes `Hide()` skip a warning or error still on screen.
- Recurrence cue: a `WarmupFailed` with reason `prime_exception`; a `TakeEnded` with reason `pipeline_crashed` and a duration of minutes for a dictation; a `TakeEnded` failed with `transcription_unavailable` after a long duration (the engine stopped late); one `FileTranscriptionFailed` per file of a batch with the same cause; an error message that the trace shows replaced by `Hidden` in the same frame.
- Guard: `TakeStartCheckTests`: `AFailedTestIsRetriedOnceFromAReloadedModelAndTheTakeGoesOn`, `ATestThatFailsTwiceStopsTheTakeAtOnceWithOneMessage`, `AStopPressedBeforeTheSecondTestFailsStillEndsWithTheMessage`, `TheMonolithicPipelineEndsWithTheSameMessageAndReason`, `AFileBatchWhoseTestFailsTwiceStopsAfterTheFirstFileWithOneMessage`, each for a throw and a native error code where it applies. `Deckle.Hud.Tests.HudHidePolicyTests` guards the HUD rule. The backend is a scripted fake that keeps reporting its model as loaded after a failure, as `WhisperBackend` does; nothing here exercises the real native library, and the real `HudWindow` has no seam, so only its decision (`HudHidePolicy`) is tested, not the wiring of `Hide()` to it.
- Side effect of the fix, found in review: testing at the start of every take made the idle unload race worse. The idle timer holds `_idleUnloadLock` for the whole native free while `WhisperBackend.IsModelLoaded` stays true until `whisper_free` returns, and `EnsureModelLoaded` skipped the lock when the model looked loaded, so a hotkey press during the unload ran the test inference on a context being freed. `EnsureModelLoaded` now always takes the lock; guard: `ATakeStartedDuringAnIdleUnloadWaitsForTheFreeBeforeItsTest` (reaches the timer's unload by reflection, the callback has no seam).
- Interpretation: a model that fails to load in the retry gets its own `Model load failed` message from `LoadModel`, not the new one; the take still ends at once, with reason `model_not_loaded`.

## A refused microphone check logged an unreadable code and no stage, so a missing DLL read as a device failure

- Trigger: the microphone check before a dictation (`MicrophoneCapture.Probe`) refused, observed 2026-11-07 on v0.87.14 when `portaudio.dll` was not beside the app (`Deckle.Audio.Tests/PortAudioDeploymentBugNotes.md`).
- Observed: `MicrophoneUnavailable` wrote `phase=probe | hresult=�￿\u0000`, and no line said which step refused. The only readable code was the HUD's `-10000`, which a refusing device can also give.
- Cause of the unreadable code, established from the code and that log line: `MicrophoneUnavailable(string, uint)` called `WriteEvent(id, phase, hresult)`. `EventSource` has no typed `(string, uint)` overload, so the call bound to `(string, long)` while the event's metadata, built from the method, declared a `uint`. The in-process listener decoded that payload as text. How exactly the decoder reached a string is inferred, not traced.
- Cause of the missing stage, established from the code: `Probe` returned the provider's code and dropped `CaptureOpenResult.FailedStage`; only `Record` logged `MicrophoneOpenFailed` with its stage.
- Violated invariants: an event method hands `WriteEvent` exactly the types it declares, or goes through the `object[]` overload; a refused open logs the step that refused, whoever asked for it.
- Fix: `MicrophoneUnavailable` (version 3) carries `error_code` as the string `MicrophoneCapture.FormatErrorCode` writes, hex for an HRESULT and decimal for a PortAudio error. `Probe` logs `MicrophoneOpenFailed` with `purpose=probe`, its stage and its code before returning.
- Recurrence cue: `�` or other control characters in a numeric field of `log.jsonl`; an event method whose parameters other than strings are `uint`, `ulong` or another type outside `WriteEvent`'s typed overloads; a `MicrophoneUnavailable` at `phase=probe` with no `MicrophoneOpenFailed` just before it.
- Guard: `DeckleWhispSourceTests.TheMicrophoneIncidentCarriesItsCodeAsAPersonQuotesIt` and `Deckle.Audio.Tests.DeckleAudioSourceTests.ARefusedProbeLogsTheStageThatRefused`. Not checked: that the first test failed against the version 2 signature, since the parameter type changed with it. Other event methods with the same overload trap are not scanned for.
