# Folders event id bug notes

## Two branches gave the same event id to different events, and the whole provider went silent

- **Trigger:** Branch `feat/folders-folder-icon` added `EvtFolderIconChanged = 50` and `EvtFolderIconChangedDetail = 51` in `DeckleFoldersSource.cs`. Branch `feat/folders-file-list` added `EvtItemLaunched = 50` and `EvtItemNotLaunched = 51` in `Launching/DeckleFoldersSource.Launching.cs`. Both were built side by side on 2026-11-15, each told to take a block of its own, and each took the first free one, 50 to 59. Merging them into `feat/folders-wave-1` raised no conflict: the constants sit in different files.
- **Observed symptom:** Nine tests of `Deckle.Folders.Tests` failed at once on the merged tree, while each branch passed alone (211 and 212 passed). Most of them observe unrelated events (size scan, added folders, photo marks). An `EventListener` received only one `EventSourceMessage` with id 0 from `Deckle-Folders`, never the expected event. The app built and its self-check passed: nothing there reads the provider's events. Observed in the test run, not in the app; the merge never reached main.
- **Cause:** An `EventSource` whose `[Event]` attributes share an id cannot build its event table. The runtime then reports one `EventSourceMessage` and writes none of the provider's events. Confirmed: moving the file tool's two events to 60 and 61 made the nine tests pass again.
- **Violated invariant:** Every `[Event]` method of an `EventSource` has its own id, across all the partial files of the source. The trap is commented where the file tool's block starts, in `src/Deckle.Folders/Launching/DeckleFoldersSource.Launching.cs`.
- **Recurrence cue:** Many observability tests of one provider failing together, with `EventSourceMessage` as the only event in the collection; a merge that adds `public const int Evt... = N;` on both sides; two tasks run in parallel that are each told to "take the next free block". The same bug was met in `Deckle-Whisp` on 2026-11-07 (`tests/Deckle.Transcription.Tests/WhispEventIdBugNotes.md`), whose note already said the other providers had no guard.
- **Regression coverage:** `DeckleFoldersSourceEventIdTests.EveryFoldersEventHasItsOwnId` reads the `[Event]` attributes by reflection and lists any shared id. It failed with the duplicate and passes with the fix. It guards this provider only; the other providers of the solution, `Deckle-Whisp` apart, still have no such test.
