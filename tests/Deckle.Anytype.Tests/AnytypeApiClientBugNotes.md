# Anytype API client bug notes

## A refused API request wrote an Error on every request and carried the server's text

- **Trigger:** The Anytype backend keeps refusing the client's requests (a revoked key answers 401 to each one, a foreign process holds the endpoint so no request is sent), or a write loses a version race that its caller then retries.
- **Observed symptom:** Each refused request wrote its own Error line, with no line to say the run had ended, while a connection failure was already coalesced into one incident. The Verbose detail of a v2 refusal carried the exception message, which embeds the API envelope (message, issues, hint) and the request path; the v1 detail carried an excerpt of the body. A stale-version 409 on a write the caller re-reads and retries (`IsStaleEtag`) was an Error as well. These are readings of the code and of the auditor's finding, not a captured journal.
- **Cause:** Only the transport failure had streak logic. The `http_status` and `untrusted_endpoint` failures called `ApiRequestFailed` directly on every request, and the detail was built from the exception or the body instead of from the machine code.
- **Violated invariant:** A degradation that repeats is one incident, opened by one line and closed by one line with its count. A log line carries machine facts: the status and the error code, never free text from the server, which may quote what a person keeps in Home. A refusal the caller expects and handles is not a failure.
- **Recurrence cue:** An `ApiRequestFailed` written outside `ApiFailureIncidents`, a detail built from `Message`, `ApiMessage`, `Hint` or a body excerpt, or a new status the callers treat as control flow that still reaches the journal.
- **Regression coverage:** `ApiFailureIncidentTests` pins the one-opener, one-closer shape for identical refusals and for an untrusted endpoint, the code-only detail (including a non-envelope body), and the stale-version case writing no journal line. A 404 stays an Error on purpose: no caller of the clients branches on it, so nothing in the code says it is expected. The v1 client shares the incident class but has no test of its own.
