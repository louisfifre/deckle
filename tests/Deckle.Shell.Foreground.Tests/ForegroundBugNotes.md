# Foreground watcher bug notes

## Hidden Alt+Tab switcher read as the fullscreen foreground

- **Trigger:** Alt+Tab to another window. Explorer's switcher is `XamlExplorerHostIslandWindow`, a transparent window the size of the monitor, and Explorer can raise an `EVENT_SYSTEM_FOREGROUND` naming it after the chosen app already holds the foreground.
- **Observed symptom:** Louis reported on 2026-11-10 that the taskbar cover often stayed down while he worked in Claude Code, until he clicked the taskbar and came back. His diagnostics trace for that day shows the pattern at each stuck switch: `ForegroundChanged` for the target app, then `explorer | fullscreen=geometry` about 1 ms later, then `CoverHidden reason=fullscreen_enter`, with no further foreground change for up to 412 s. A probe the same day caught an event naming the switcher while it was invisible and `GetForegroundWindow` returned Explorer's `ForegroundStaging`. The probe did not capture the trailing event itself; that it names the same hidden switcher is read from the trace, not observed directly.
- **Cause:** `ForegroundWatcher.OnForegroundEvent` probed the event's hwnd as the new foreground without checking it against `GetForegroundWindow` at delivery. `FullscreenStageOf` then judged that window by size alone: a hidden window covering the monitor passed the geometry stage. The stale snapshot stayed current until the next real switch.
- **Violated invariant:** The snapshot describes the window Windows names as foreground when the event is handled, and only a drawn window (visible, not cloaked) reads as fullscreen. See the comments on `ForegroundWatcher.OnForegroundEvent` and `FullscreenGeometry.ReadsAsFullscreen`.
- **Recurrence cue:** A WinEvent handler that publishes the event's hwnd as state; a geometry-based fullscreen test that does not ask whether the window is drawn; a cover hidden for `fullscreen_enter` right after a switch, with Explorer as the foreground process.
- **Regression coverage:** `FullscreenGeometryTests.A_hidden_window_covering_the_monitor_never_reads_as_fullscreen` pins the rule the geometry stage applies. The Win32 reads (`IsWindowVisible`, `DWMWA_CLOAKED`, `GetForegroundWindow` at delivery) and the event ordering live in the hook callback, which has no natural seam; no test reproduces the out-of-order event.
