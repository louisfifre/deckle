# Recording outline bug notes

## The recording outline stopped pulsing with the voice

- **Trigger:** a dictation on a machine where the Windows "Animation effects" preference (Settings ▸ Accessibility ▸ Visual effects) is off, from v0.85.0 on.
- **Observed symptom:** reported by the maintainer (2026-11-07): the HUD's voice-level outline no longer pulses with the microphone while dictating. Not reproduced on screen by an agent; the running app was not driven.
- **Cause:** commit 14ae67cc (2026-11-06) removed the `Overlay.Animations` switch, on by default, and made every HUD animation follow the Windows preference through `SystemAnimationPreference`. Until then the microphone response hung on that Deckle switch, and the Windows preference only governed simple transitions. `ProcessingStroke.UpdateLevel` began with `if (!_animationsEnabled) return;`, and `CreateRecordingStroke` started the outline at opacity 1 when animations were off, so the outline stood still at full opacity for the whole take. Established: on the maintainer's machine `SystemParametersInfo(SPI_GETCLIENTAREAANIMATION)` returns false (the system value behind the "Animation effects" toggle, which `UISettings.AnimationsEnabled` reads; the app's own reading was not logged), and the running build is 0.85.1, which contains 14ae67cc. Inferred from the code, not observed: that this early return is what the maintainer saw.
- **Ruled out:** the voice-level mapping (`AudioLevelMapper`, anchored on `CaptureSettings.VoiceLevelDbfs` since c4c248e9). With the stored level at −48 dBFS the window runs from −48 to −28 dBFS; the dictation heartbeats of 2026-11-07 log speech between −28 and −39 dBFS and pauses between −50 and −60 dBFS, which the map turns into about 0.67 to 1 and 0. The hops from capture to the HUD (the capture loop → `MicrophoneCapture.AudioLevel` → `TranscriptionEngine.AudioLevel` → `HudWindow.OnAudioLevel` → `HudChrono.UpdateAudioLevel`) were read and are intact.
- **Invariant:** the recording outline answers every microphone level sample, whatever the animation preference; the preference only takes away the glide between samples, as it does for the pause countdown (`interpolate: false`). The comment on `ProcessingStroke.LevelStep` states it at the line.
- **Fix:** `UpdateLevel` takes its step from `ProcessingStroke.LevelStep`, which always carries the level and glides 50 ms only with animations on; without the glide the opacity is written directly. The recording stroke starts dark in both cases, and turning the preference off mid-take no longer parks the outline at full opacity.
- **Recurrence cue:** a motion gate that returns before a live measurement reaches the screen (microphone level, countdown progress), or a new animation preference that folds functional feedback in with decorative motion.
- **Regression coverage:** `RecordingLevelStepTests.TheOutlineFollowsTheMicrophoneWithAnimationEffectsOff` pins the step `UpdateLevel` applies. The Composition write itself has no headless seam: a test cannot catch an early return placed in `UpdateLevel` before `LevelStep`. Manual check: with "Animation effects" off, dictate and watch the outline darken in pauses and light up on words.
