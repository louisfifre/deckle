# Settings expander items bug notes

## The backup fold on the General page closed the app when it opened

- **Trigger:** Opening the "Settings backup" fold (`GeneralBackupExpander`) on the General page of the Settings window. Seen on 2026-10-14 at 19:09, on the Release build of `feat/settings-pass` at 4c90a401, while Louis was dictating a review. The fold had not been opened before on that build.
- **Observed symptom:** Deckle closed. `%LOCALAPPDATA%\Deckle\diagnostics\errors.jsonl` holds a `COMException` "Cannot apply a Style with TargetType SettingsCard to StackPanel", thrown from `SettingsExpander.ItemsRepeater_ElementPrepared`; `app.jsonl` places it about thirty seconds after the navigation to General.
- **Cause:** Established from the log and the page's XAML. The fold's `Items` held a `StackPanel` (`BackupLocationHost`), the panel the composer needs to compose the backup location card into. The Community Toolkit `SettingsExpander` (8.2.250402) applies its SettingsCard item style to every element of `Items` when its `ItemsRepeater` realizes them, which happens at the first expand, so the style threw on the panel. The composer's own folds never hit it: `SettingsComposer.Folds.AddChildToExpander` adds the built `SettingsCard` straight to `Items`, and wraps an advisory `InfoBar` in a borderless card for the same reason. The General page's bespoke fold bypassed that path. The host was in the fold on `main` as well, so the crash was latent there; whether anyone opened that fold on a `main` build is not known, this is inferred from the absence of a report.
- **Violated invariant:** Every entry of a `SettingsExpander`'s `Items` is a `SettingsCard`. A composer that feeds a fold composes into a panel of its own and moves the cards into `Items`, as `GeneralPage.ComposeApplicationDataSection` does since the fix (31dde575).
- **Recurrence cue:** A `StackPanel`, a `Grid` or any element that is not a `SettingsCard` inside `SettingsExpander.Items`, in XAML or from code; a fold that nothing opens during a review. Same family as the Button style applied to a ToggleButton that blanked every page the same day (4c90a401): a WinUI style whose `TargetType` the element is not.
- **Regression coverage:** None. The failure happens inside the Toolkit's `ItemsRepeater` at expand time, in the WinUI visual tree; the Catalog tests run without a WinUI runtime and no test project covers the Settings pages. A guard would be a UI test that expands every fold of every page, which `deckle-testing` targets and does not have yet.
