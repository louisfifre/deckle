# 2. Windhawk engine source survey (GitHub ramensoftware/windhawk HEAD 0cfc358, 2.0.0-alpha.7, 2026-10-10)
Layout. `src/windhawk/app/` builds `windhawk.exe` (~7.3k lines: tray daemon, service, `engine_control.cpp`, update checker, UI launcher). `src/windhawk/engine/` builds `windhawk.dll` for Win32/x64/ARM64 (48 own files, ~12k lines: `all_processes_injector`, `new_process_injector`, `dll_inject`, `inject_shellcode/`, `customization_session`, `mods_manager`, `mod.cpp` ~3.3k lines, `mods_api.*`, `symbol_enum.cpp`, `storage_manager`). `engine/libraries/` vendored ~288k lines (MinHook, SlimDetours adapter, Zydis, binaryninja arm64 disassembler, phnt, wow64pp, thread-call-stack-scanner, DIA SDK). `src/windhawk-core` (Rust 2.0) = core DLL + CLI + UI (WebView2).
Required to run mods: a host that loads `windhawk.dll` and calls its exports; `engine.ini`; mod DLLs + config. Symbol-hooking mods also need `symsrv_windhawk.dll` + `msdia140_windhawk.dll`.
Mechanism. Host: `LoadLibrary(windhawk.dll)`, `GlobalHookSessionStart`, then `GlobalHookSessionHandleNewProcesses` on a 1000 ms timer (`app/main_window.cpp:16`). Portable mode = no service, tray daemon hosts the engine. Injection: `NtGetNextProcess` enumeration, include/exclude filters, `VirtualAllocEx` + `WriteProcessMemory` shellcode + `CreateRemoteThread`, shellcode calls export `InjectInit`. Children: `CreateProcessInternalW` hook + `NtQueueApcThread`. Mods unload when the host exits. Symbols: DIA + symsrv, path `srv*<AppDataPath>\Symbols*https://msdl.microsoft.com/download/symbols`; online cache `https://ramensoftware.github.io/windhawk-mod-symbol-cache/<modId>/` tried first (`mod.cpp:3010`); results cached per mod. Hooking: MinHook (BSD-2) through MinHook-Detours over SlimDetours (MIT), `engine/stdafx.h:84-88`. Settings pickup: `FindFirstChangeNotification` on `Mods`, 200 ms debounce, `ChangeMarker` = (`LibraryFileName`, `SettingsChangeTime`) → reload or `Wh_ModSettingsChanged` (`mod.cpp:3166-3200`).
Mod API. Built with clang++ (llvm-mingw), `-include windhawk_api.h`, linked to `windhawk.lib`; engine resolves `Wh_ModInit`, `Wh_ModAfterInit`, `Wh_ModBeforeUninit`, `Wh_ModUninit`, `Wh_ModSettingsChanged` (`mod.cpp:1552-1643`). ABI append-only.
Cadence. Engine 6 versions in 2025, no note mentions a Windows update breaking the engine. Mods ~30 versions/year.
Licences. Root LICENSE GPLv3 (engine, app, core). The eight mods GPLv3. Third-party: MinHook BSD-2; SlimDetours, thread-call-stack-scanner, phnt, Zydis, WIL MIT; wow64pp Apache-2.0; DIA/msdia/symsrv Microsoft terms (unverified).
Build. VS 2022, MSBuild, v143, C++23, SDK 10.0; NuGet `wtl 10.0.10320`.

# 4. Landscape (verified 2026-10-17/18; [V] verified, [I] inferred)
ExplorerPatcher GPL-2.0 [V]: per-build offsets by hash → PDB download → registry cache → silent disable, some pattern scanning, https://github.com/valinet/ExplorerPatcher/wiki/Symbols . StartAllBack, Start11 proprietary. TranslucentTB GPL-3.0, 2026.2 [V], ExplorerTAP, no symbols. windows-11-taskbar-styler derived from ExplorerTAP, "only one XAML diagnostics consumer at a time" [V]. UWPSpy (m417z) same API [V].
Full replacements with tray: Seelen UI AGPL-3.0 (tray by `SetWindowsHookExW(WH_CALLWNDPROC)` with `sluhk.dll` on explorer's tray thread, state from `HKCU\Control Panel\NotifyIconSettings`) [V]; yasb MIT; Zebar + MIT crate `systray-util` (own `Shell_TrayWnd`, WM_COPYDATA forwarding, `TaskbarCreated` broadcast; reading existing icons Windows 10 only) [V]; Cairo Shell / ManagedShell Apache-2.0 [V].
PowerToys Command Palette Dock (MIT, 0.98, 2026-03): AppBar toolbar, clock and perf bands, no tray, no window buttons; https://learn.microsoft.com/windows/powertoys/command-palette/dock .
Symbol resolution: Windhawk online cache https://github.com/ramensoftware/windhawk-mod-symbol-cache produced by scripts (extract `SYMBOL_HOOK` blocks from mods → download binaries by Winbindex metadata from msdl → extract RVAs → one text file per mod and binary; key `pdb_{fingerprint}` or `pe_{arch}_{ts}_{size}_{name}`, content `1#{binary}#…#{symbol}#{rva}`). Rebinding on rename: `SYMBOL_HOOK` takes a braced list of alternative names, added by hand; no project rebinds automatically [V].
Hook-free: `TaskbarSi` ignored since 22H2 Moment 2 [V]; `TaskbarGlomLevel` honoured again from 23H2 [V]; `TaskbarDa` blocked by UCPD on 24H2 [V]; `EnableAutoTray` dead [I], replaced by per-icon `IsPromoted`; vertical taskbar flags 59213768, 61161244 [V]. DWM accent on Shell_TrayWnd undocumented and the Win11 background is XAML [I].
Robustness: AppBar + tray protocol > XAML Diagnostics (silent partial failure) > registry > symbols/patterns.

# 5. Reading of the taskbar cover code (Deckle)
`TaskbarLocator.cs` (Deckle.Shell.TaskbarCover): `FindWindowEx(…, "Shell_TrayWnd")` + `Shell_SecondaryTrayWnd` loop, `GetWindowRect`, `MonitorFromWindow`, `GetMonitorInfo`, edge from `CoverGeometry.EdgeOf`, DPI from `GetDpiForMonitor`; no stored width (`TaskbarCoverNativeMethods.cs:58-67` explains why ABM_GETTASKBARPOS was dropped). `TaskbarCoverHost.LifecycleAndWindow.cs:138` registers `TaskbarCreated`; `TaskbarCoverHost.CallbacksAndMessagePump.cs:80-84` rebuilds on it, also on `WM_SETTINGCHANGE`, `WM_DISPLAYCHANGE`; the tray icon (`src\Deckle.Shell\TrayIconManager.cs:112, 179-184`) re-adds on it; a message-only window never receives the broadcast (`MessageOnlyHost.cs:15`). Sub-pages: `SettingsModuleDescriptor.ParentId` (`src\Deckle.Catalog\SettingsModuleDescriptor.cs:62`); first child turns the parent into a node whose own page becomes "General" (`src\Deckle.Settings\SettingsWindow.xaml.cs:186-240`); examples Whisper and Autocorrect. Persistence: `TaskbarCoverSettingsService` singleton over `JsonSettingsStore<T>` → `AppPaths.UserDataRoot\modules\taskbar-cover\settings.json`. Wiring without DI: `App.Startup.Modules.cs:78` `InitializeTaskbarCover()`, `App.TaskbarCover.cs` builds the host, subscribes `Changed`, reconciles Start/Stop. A sibling module needs: settings record, service, descriptor, SettingsSearch, page + ViewModel manifests, Strings, Source logger, `App.<Name>.cs`, entries in `App.Startup.Modules.cs` and `App.Startup.Settings.cs`; tests in `tests\Deckle.Shell.TaskbarCover.Tests\`.
