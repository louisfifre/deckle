# Deckle.Home — Journal

## 2026-08-13

- **`create` accepts a template, named the way the app shows it.** An item may carry `template`, the human label of one of the type's templates; the gesture resolves it against the live type at call time and sends the resolved id as `template_id` in the create body, for coded and free-titled types alike. It composes with `text` and with `properties` — a template is a starting structure, not an alternative to the body. Resolution matches the exact name first, then a case- and diacritic-folded name so a dropped accent still lands; no match or an ambiguous one refuses in the surface's usual shape, naming every template the type has.
- **Template ids are Home coordinates and stay out of the code.** The dev-space module may hardcode its template ids; Home may not — the privacy boundary forbids a live-object id as a compiled constant. Home therefore resolves by name against the live space, reading the type's templates through the new `AnytypeApiClient.ListTemplatesAsync` (`GET /v1/spaces/{space}/types/{type}/templates`, paginated like its neighbours). The type's own id comes from the runtime schema snapshot (`HomeSchemaRuntime.TypeId`), the same seam that already discovers the Zone type key. The template list is read at most once per `create` call — one type per batch — and never cached beyond it: these are live coordinates, and freshness beats a stale hit.
- **`POST /objects` still ignores a type's default template.** Confirmed again while wiring this: the API applies a template only when `template_id` is sent explicitly, and `template_id` composes with the rest of the body rather than replacing it. A `create` without `template` therefore issues no templates request at all.
- **`restock_threshold` leaves the required schema.** The property came in with the equipment block, was never asked for, and the owner deleted it in the app — where it then held the whole guichet closed, a required property absent from the live space failing conformity. Its French term went with it in the same move: `HomeTerms.PropertyName` throws on a missing term for any required key, so schema and terms can only move together. Conformity tolerates surplus, so a space still carrying the property keeps working.

## 2026-08-12

- **The compiled surface follows the space-reboot grill (home repo, mcp/action-surface.md carries the full record).** The Home space was recreated from zero on the clean manifest; four rulings by Louis land here as one focused change. (1) `utensil` (Ustensile de cuisine) joins the equipment family: kitchen gear was crowding `device`, whose life is electronics-heavy; same doctrine as a device — may join a Système via `part_of`, no gate. (2) `domain` gains `electronique` (the BRESSER wall clock is électronique, not informatique — option born in the app). (3) `supplier` leaves the closed vocabularies: real purchases (Decathlon, LDLC, Rakuten, Logitech, Particulier) outgrew the compiled six, so it now resolves like `manufacturer` against live options grown in the app. (4) The never-delete point rule falls — Louis disowned the absolutism recorded at the 2026-07-21 grilling. The living rule: Existence = Déposé describes a real element off the wall; an entry mistake retracts through the two-step delete while the point is unsurveyed (no Date de relevé) and referenced by nothing; allocation never recycles a number. `RefusePointDelete` now enforces that invariant instead of the type, and the server instruction says so.
- **`worksite` is layout `action` (Louis, 2026-08-12), correcting the 2026-08-05 note below.** The chantier closes through Statut = Terminé all the same — the done box exists but Statut carries the six-state lifecycle; `complete` keeps its polymorphic behavior unchanged. Only the self-generated manifest diverged; conformity never checked layouts.
- **Conformity is a required subset — manifest-only properties write without a Deckle change.** Established while sequencing the reboot: `Validate` tolerates surplus and the property writer resolves against the live type's attached properties, so `needed` (Prendre) and `errand_category`, applied by the space manifest but absent from the compiled contract, are writable through the existing verbs. Only a REMOVAL (aisle/quantity leaving the errand block) would break conformity; that cleanup waits as its own later change.

- **The model rework: 13 English-keyed types, the point merge, the equipment triad, human titles.** The Home schema moves from 13 French-keyed types to 13 English-keyed ones in five families (floor/room/point/circuit/panel, system/device/component, plant/idea/errand, worksite/todo). The ten former wall-point types merge into one `point` type whose nature is the frozen `category` select — no longer a type discriminator. Equipment gains a triad: `system` aggregates, `device` stands alone (optionally joining a system via `part_of`), `component` only exists inside its system — the surface refuses its creation without one, and doubt goes to `device` since retyping is cheap. Titles are now human names, written for the whole household; the immutable identity code of `room`, `point`, `circuit`, and `panel` moves to the `code` property. This inverts the 2026-07-21 "inventory codes live in object titles" decision and legitimizes the `code` property that decision once forbade.
- **Labels externalized to `Terms/terms.fr.json`.** Every Anytype-visible label — type names, property names, closed-vocabulary options — now lives in one embedded terms file per language, loaded by `HomeTerms` (the pattern shipped by `Deckle.Travel`), instead of hard-coded C# strings. The freeze this forces reactivated the multilingual-review idea shelved earlier: a second language is now a file addition, not a code change.
- **`floor` is labeled « Zone », not « Étage » (Louis, 2026-08-10).** The grouping is an assemblage of rooms — Extérieur is not a storey — modeled like the pinned sections: a collection of pièces. « Espace » was considered first and rejected the same day: it collides with the Anytype space vocabulary (« l'espace Home »). The English key `floor` predates the rename and stays as the technical coordinate (the `room.floor` property was already applied live); only the words moved. The rename also dissolves the type/object homonymy where a type named Étage would have contained a collection named Étage.
- **The `floor` type cannot be created through the API.** Verified live on the fresh space (2026-08-10): the Anytype API refuses to create a TYPE with collection layout ("invalid type layout: collection" on POST /types); whether collection objects of an existing such type can be API-created remains untested. `floor` is therefore app-created; its real key is discovered at runtime from the live schema snapshot (`HomeSchema.FloorTypeKey`) rather than compiled as a constant, and floor-dependent features refuse with guidance while the type is absent instead of failing the whole schema closed.
- **Fresh-space key arbitrations recorded in the home repo manifest.** Two keys collided with Anytype's built-ins and were arbitrated there, not in this module: `todo` (built-in task collision) and `plant_exposure` (built-in exposure collision).
- **The desktop-pairing channel is dead (Louis, 2026-08-10).** Every write now goes through the bot's MCP surface; there is no parallel desktop-paired path. The 57-object refill of the fresh space is driven entirely through the surface's `create`/`update` verbs from `mcp/refill-fixture.json` in the home repo.
- **The Zone type is app-born; its objects are ordinary API objects (verified live, 2026-08-10 evening).** Research on the developer docs and the anytype-heart/anytype-ts sources settled the earlier "remains untested" point and closed the type-creation question for good: the REST create/update layout whitelist (basic/profile/action/note) is a deliberate, unchanged gate at JSON decode; no API version is newer than 2025-11-08; and the app's own Format Liste path travels the internal gRPC channel behind an `AccountAuth_Full` session that only the wallet mnemonic can mint — the local pairing flow tops out at scopes that deny `ObjectCreateObjectType`. Louis created the Zone type in the app (app-derived key `zone`, not `floor` — exactly why the runtime discovery exists; it found the type without a rebuild). The three zone collections were then API-created as plain objects of that type, membership landed through schema-admin, and the 20-room floor batch exercised the repaired scalar-relation path live, including one room carrying two zones.

## 2026-08-05

- **Life types join the surface without the code grammar.** `idee`, `course`, and `outil` are creatable through the same five gestures: no code, a free title for course/outil, a body-derived title for idee (the dev-space capture shape — single-line text of ≤80 chars becomes the whole title, longer text keeps its head as title and the full text as body). The PIÈCE-CAT grammar and element invariants stay strictly inventory-side.
- **Files properties refuse MCP writes.** `facture` and `documents` belong to the validated contract, but their values are deposited in the app; the property writer fails them with guidance instead of silently writing text.
- **"The node already has a parent" was ours, not Anytype's.** The `etage` relation failure was a client-side System.Text.Json exception: in the property writer, `value is JsonArray array ? array : [value]` target-types the collection expression as a **JsonArray**, and building it around a scalar node that already belongs to the caller's properties object re-parents it and throws. Scalar selectors hit the bug, array selectors dodge it — which is why `circuit` writes (arrays) passed while `etage` (scalar) failed, and why the key-collision hypothesis was wrong. Fixed by wrapping scalars in a plain array; verified live by setting AT's Étage to Extérieur through the patched path. The same pattern remains in `TravelPropertyWriter` (flagged as a separate task).
- **Work types are pilotage, not the dev-space PM model (decisions Louis, 2026-08-05).** `chantier` and `tache` join the surface with dedicated verbs (`chantier_create`, `tache_create`, `complete`, `chantier_overview`) because typed commands spend fewer tokens than generic gestures — the five gestures stay as the fallback. No intervention journal: done tasks are the record. Creation stays loose everywhere: a name suffices, properties land when known. Orphan tasks are allowed; the chantier is for real works.
- **Anytype's link graph is not a domain reference.** The live smoke test showed objects carry system objects-properties (`links`, `backlinks`, `creator`, `last_modified_by`); counting them in the delete guard made a tâche and its chantier hold each other undeletable. The guard now ignores them — only domain relations refuse a deletion.
- **`complete` is polymorphic on the completion signal.** A `tache` or `course` gets the native action-layout `done` checkbox (outside the property contract, entry built directly); a `chantier` gets `statut = Terminé` (its basic layout has no done box) and the reply counts still-open tasks.

## 2026-07-21

- **Room registry is live data.** Room codes are read from `Pièce` objects in the configured Home space; no room list belongs in source or local configuration.
- **Applied schema keys are the contract.** Electrical circuits and distribution boards use `circuit_elec` and `tableau_elec`. Inventory codes live in object titles; there is no `code` property.
- **Category option keys are provider-local.** Anytype derives live tag keys from their labels, so the domain resolves the normative category code through the full applied label and never assumes the manifest key survived creation.
- **Select inputs are keys; Anytype writes use live tag ids.** The Home surface accepts the normative tag key or label, resolves it against the configured space, and sends the matching tag id in object properties.
- **Collection membership is not an object relation.** Home create/update exposes collection membership separately from `properties` and writes it through Anytype's list-member endpoints.
